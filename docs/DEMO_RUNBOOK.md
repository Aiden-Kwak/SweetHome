# SweetHome 실전 데모 실행안

2026년 10월 16일 로컬 웹 5174, API 8001에서 실제 조작한 흐름을 기준으로 작성했다. 이후 서울 리전 Cloud Run에 웹과 API를 배포하고, 공개 웹에서 Gemini 추출, 서울 25개 구 계산, 지역 조건 변경과 JSON 저장까지 확인했다. 기존 기획의 목표 기능과 현재 동작을 구분한다.

## 핵심 메시지

정책입안자가 법을 시행하기 전에 적용 지역, 사업 조건과 가구 자격을 바꾸어 영향 경로를 비교하는 도구다. 집값을 맞히는 서비스보다 '왜 결과가 달라지는지 다시 계산하고 설명할 수 있는 정책 실험 도구'로 소개한다.

첫 화면의 2025년 역사적 시나리오는 합성 예시다. 새 문서 실험은 별도 계산 경로이며, 기존 지도와 가구 행동 비중을 방금 업로드한 문서의 결과로 소개하지 않는다.

## 권장 구성: 본편 3분, 보조 시연 1분

본편은 공급 개정안 하나로 완결한다. 가구 영향과 그래프 편집은 추가 시간이 있거나 질의응답에서 보여준다. 한 발표에서 모든 탭을 빠르게 훑는 대신, 입력 한 개를 바꿨을 때 결과가 달라지는 장면을 핵심으로 삼는다.

| 시간 | 실제 조작 | 보여줄 가치 |
| --- | --- | --- |
| 0:00-0:20 | 첫 화면에서 '정책 문서 검토'를 연다. | 정책을 시행하기 전에 영향을 검토한다는 문제를 제시한다. |
| 0:20-0:45 | '주택법 시행령 개정안: 주상복합 건축허가 기준 완화'의 검토 요약을 추가하고 '자동 조문 추출'을 누른다. | 공식 자료 출처와 변경 전후 300, 500세대를 보여준다. |
| 0:45-1:10 | 세대수 규칙을 선택한다. 가정 실험, 서울 25개 구, 공급 조건, 최종 입력을 확인하고 실행한다. | 사람이 적용 조건을 검토하는 단계를 보여준다. |
| 1:10-1:50 | 서울 지도의 강남구를 선택하고 오른쪽 공급 경로를 설명한다. | 10개 사업, 400세대, 전환 비율 25%가 1,000세대의 공급 시점 변화로 이어지는 계산을 보여준다. |
| 1:50-2:25 | '조건을 바꿔 다시 계산'에서 강남구 사업 수만 10개에서 20개로 바꾸고 확인 후 실행한다. | 강남구 민감도만 -0.5%에서 -1.0%로 달라지고 다른 지역은 유지되는 모습을 보여준다. |
| 2:25-2:45 | 원문과 계산 근거를 연 뒤 JSON 저장을 누른다. | 원문, 입력 가정, 결정식과 실험 ID를 추적할 수 있다. |
| 2:45-3:00 | '시행 전에 대안과 조건을 비교한다'는 메시지로 마무리한다. | 예측 숫자보다 재현 가능한 의사결정을 강조한다. |

위 수치는 기본 시나리오 입력값에 따른 민감도다. 지역별 관측 통계 또는 실제 집값 전망이 아니다. 모든 구의 시작값이 같으면 결과도 같다. 지역 차이를 만들려고 무작위 값을 넣지 않는다.

### 클릭 순서

1. '정책 문서 검토'에서 공급 개정안의 '검토 요약 추가'를 누른다. 기존 문서가 남아 있다면 '새 문서로 시작'으로 먼저 정리한다.
2. '자동 조문 추출'을 실행한다. 추출 방식 배지에 실제 사용한 엔진이 표시된다.
3. '이번 실험에 적용할 규칙'에서 세대수 기준 300, 500을 선택한다. 같은 값이 요약과 발췌에서 반복 추출되면 첫 후보를 사용한다.
4. 개정안은 입법예고이므로 '시행일과 무관하게 적용되었다고 가정하여 실험합니다'를 직접 선택한다. 시행일을 임의로 만들지 않는다.
5. '서울 25개 구 선택'을 누른다. 기본 시작 지역이 서울 밖이면 '모두 해제' 후 서울을 선택한다.
6. 공급 시작값을 확인한다. '선택한 기준 외의 사업 요건은 충족한다고 가정하고…'와 최종 입력 확인을 선택한다.
7. 실행 후 강남구를 지도 또는 목록에서 선택한다. 25개 지역 비교 표를 펼칠 수 있다.
8. 재계산할 때 '지역별 공급 조건 수정'을 펼치고 '수정할 지역'에서 강남구를 선택한다. 사업 수만 20으로 변경한다.
9. 공급 조건과 최종 입력 확인을 다시 선택하고 실행한다. 변경된 조건은 같은 값으로 재실행하면 동일한 실험 ID를 만든다.
10. 창을 닫아도 새로고침 전까지 입력과 결과가 유지된다. 첫 화면의 '새 정책 결과 다시 보기'로 복귀한다. 새로고침에 대비하려면 JSON을 저장한다.

## 가구 영향 보조 시연

### 결과를 사용자별로 해석하기

결과 상단의 '대상별 인사이트 보기'를 누르면 지도 아래의 안내 영역으로 이동한다. '정책입안자'는 적용 대상과 제외 대상, 공급 전환 조건, 보완할 요건과 다음 실험을 안내한다. '내 집 마련 준비자'는 선택한 가구의 예산 변화, 입주 일정과 실제 신청 전 확인 사항을 안내한다. 금융 실험에서는 가구 사례를 바꿀 수 있다. 지도에서 지역을 바꾸면 공급 안내도 같은 지역의 결과로 갱신된다.

안내는 현재 응답의 값과 정책 유형별 설명 문구를 조합한 해석이며, Gemini가 새 수치나 매매 조언을 생성하는 기능은 아니다. 재계산 버튼은 입력 검토 화면으로 돌아간다. JSON은 원문과 계산 결과를 저장하며 화면의 안내 문구는 포함하지 않는다. 전세보증 설명에는 [HF 일반전세자금보증 안내](https://www.hf.go.kr/ko/sub02/sub02_01_02.do)를 연결한다.

### 전세보증 사례

금융위원회의 '보금자리론 및 청년 전세대출보증 지원 변경' 검토 요약을 새 문서로 불러온다. 본편 공급 실험을 덮어쓰기 전에 필요하면 JSON을 저장한다.

1. 추출된 '전세대출보증 한도' 2억 원, 3억 원을 선택한다.
2. 2026년 10월 16일은 안내된 시행 예정일인 10월 19일 이전이다. 시행을 가정하는 실험을 선택하거나 기준일을 시행 이후로 설정한다.
3. '무주택 신혼부부 사례에 적용'만 선택한다. 이는 합성 사례가 해당 자격을 충족한다고 가정하는 것이며 자동 자격 판정이 아니다.
4. 실행하면 보증 범위는 2억 원에서 3억 원으로, 현금 1억 원을 더한 임차 예산은 3억 원에서 4억 원으로 바뀐다.
5. 해당 가구는 +33.33%, 나머지 세 가구는 0%다. 지도는 네 사례의 단순평균 +8.33%를 보여준다. 전세보증과 임차 예산이지 매매가격 상승률이 아니다.

## 그래프와 관측 자료를 보여주는 방법

결과 창을 닫고 '지식 그래프'에서 강남구 또는 대출 관련 노드를 검색한다. 노드, 관계, 출처 메모와 실행 취소를 보여줄 수 있다. 그래프 편집은 브라우저의 검토용 편집본에 저장되며, 새 정책 실험 결과를 자동으로 반영하거나 계산식을 바꾸지는 않는다.

실거래 자료는 강남구, 성동구, 마포구의 보관 표본이다. 전체 서울 가격 데이터라고 소개하지 않는다. 연구 근거 탭은 과거 연구를 확인하는 별도 자료실이며, 모든 연구 계수가 현재 새 정책 모형에 적용됐다는 의미가 아니다.

## 영어 발표 대본

### Opening

“Before a housing policy becomes law, policymakers need to ask: who is affected, where, and why? SweetHome turns a policy document into a reviewable scenario.”

### Extraction and review

“This proposed amendment changes the mixed-use housing threshold from fewer than 300 units to fewer than 500. We review the extracted rule, choose Seoul’s 25 districts, and make our assumptions explicit.”

### Map and mechanism

“The map and the explanation come from the same calculation. Under these starting assumptions, ten projects with four hundred units each, and a twenty-five percent delivery shift, bring one thousand units forward.”

### What-if comparison

“Now I change only the number of projects in Gangnam. Its sensitivity changes, while the other districts remain unchanged. These are scenario sensitivities, not observed price forecasts.”

### Close

“We can trace the result back to the source and export every input. SweetHome helps policymakers compare alternatives before implementation.”

### Optional household scene

“For a separate rental-guarantee policy, this eligible newlywed example gains one hundred million won of guarantee coverage. Other profiles keep their existing conditions. This is a rental-budget comparison, not a house-price prediction.”

## 발표 전 필수 확인과 아직 분리된 영역

| 항목 | 현재 확인 상태 | 발표 대응 |
| --- | --- | --- |
| 공식 검토 요약 입력과 추출 | 두 예시로 브라우저 시연을 완료했다. | 본편의 기본 입력으로 사용한다. PDF 전문 업로드라고 말하지 않는다. |
| 공급 계산, 서울 25개 구, 재계산과 JSON 내보내기 | 브라우저에서 끝까지 확인했다. | 본편에 포함한다. |
| 가구 금융 조건 계산 | 신혼부부 적용 사례로 확인했다. | 보조 시연에 포함한다. |
| PDF, HWPX 파싱 | 파서 단위 테스트가 있다. 발표용 실제 첨부파일 업로드는 이번 리허설에 포함하지 않았다. | 실제 파일을 쓸 경우 같은 파일로 사전 리허설한다. 구형 HWP와 스캔 PDF는 기본 경로에서 제외한다. |
| Gemini 실제 호출 | 행사 계정의 `gemini-4-argon`을 연결했다. 클라우드 API에서 두 공식 검토 요약이 GEMINI로 응답했고, 공개 웹에서 공급 개정안의 추출을 확인했다. | 공개 웹의 자동 추출을 사용한다. 키를 설정하지 않은 기존 로컬 API는 여전히 규칙 기반일 수 있으므로 구분한다. |
| Google Cloud 배포 | 서울 리전에 `sweethome` 웹과 `sweethome-api`를 배포했다. 공개 웹에서 서울 25개 구 계산, 강남구 재계산과 JSON 다운로드를 확인했다. | 발표에서는 공유받은 공개 서비스 URL을 사용한다. [배포 안내](../infra/cloudrun/README.md)를 참고한다. |
| 실제 JEV 행동 모형, 지역 간 전이, 전체 정책 결합 | 새 문서 실험 경로에 구현되지 않았다. | 목표 기능으로 구분한다. 기존 합성 행동 비중을 새 문서 계산 결과로 사용하지 않는다. |
| 그래프 자동 갱신과 편집의 계산 반영 | 연결되지 않았다. | 별도의 검토용 그래프 편집 기능으로 소개한다. |
| 새로고침 복구 | 입력과 결과는 현재 탭의 메모리에 유지한다. | JSON을 저장한다. JSON 재불러오기 기능은 없으므로 입력 경로도 준비한다. |
| 제출물 | 앱과 별개로 점검해야 한다. | 영문 소개, Public GitHub, 데모 영상, Cloud URL을 최종 확인한다. |

클라우드와 Gemini 연결을 확인했지만, 발표 직전에 공개 주소에서 한 번 더 추출한다. 모델 사용 권한과 행사 계정의 유효기간이 유지되는지 확인한다.

## 장애 대응

- API가 꺼져 있으면 로컬 API를 복구하고 재시도한다. 브라우저만으로 전체 시뮬레이션이 실행되는 구조는 아니다.
- Gemini가 실패하면 규칙 기반을 명시적으로 선택해 제품 흐름을 시연한다. 이 대체 경로는 Google AI 실사용 검증을 대신하지 않는다.
- 파일 추출이 실패하면 같은 자료의 검토 요약으로 전환하고 입력 형식을 밝힌다.
- 외부 원문 사이트가 느리면 앱에 보관된 요약과 출처를 먼저 보여준다.
- 발표 중 새로고침하지 않는다. 다른 탭을 보여줄 때는 결과 창을 닫았다가 다시 연다.
