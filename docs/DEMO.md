# 데모 안내

현재 구현을 기준으로 한 클릭 순서, 영어 대본과 발표 전 확인 사항은 [SweetHome 실전 데모 실행안](DEMO_RUNBOOK.md)을 따른다. 아래의 원래 구성은 목표 기능을 포함한다.

## 목적

데모는 집값을 정확히 맞혔다고 주장하는 자리가 아니다. 모든 정책을 구조화하고, 정책 변경부터 가구 행동과 지역 전이까지 근거를 추적할 수 있다는 점을 보여준다.

## 권장 이야기

1. 한국 부동산 정책은 여러 규제가 동시에 바뀌어 한 정책만으로 결과를 설명할 수 없다고 말한다.
2. 최근 정부의 부동산 정책 개편안 PDF 또는 한글 파일을 업로드한다.
3. Gemini가 정책을 개별 규칙으로 분해하고 기존 정책과 달라진 내용을 보여준다.
4. 적용 지역, 시행일, 대상과 예외를 확인하고 시뮬레이션을 실행한다.
5. 수도권 지도에서 지역별 변화 범위와 인접 지역 전이 가능성을 확인한다.
6. 지도 옆 페르소나 카드에서 가구별 구매력과 행동 변화를 비교한다.
7. 지역 또는 페르소나를 선택해 정책 원문과 연구 Claim까지 이어지는 경로를 연다.
8. 완전성 상태와 합성 데모 한계를 보여주며 신뢰 원칙을 강조한다.

## 3분 구성

| 시간 | 내용 |
| --- | --- |
| 0:00부터 0:20 | 문제와 제품의 한 문장 가치를 설명한다. |
| 0:20부터 0:50 | 최근 정책 파일 입력과 원자 규칙 분해를 보여준다. |
| 0:50부터 1:45 | 수도권 지도, 시간 변화와 지역 전이를 보여준다. |
| 1:45부터 2:20 | 페르소나별 구매력과 행동 변화를 보여준다. |
| 2:20부터 2:45 | 인과 그래프와 연구 근거를 보여준다. |
| 2:45부터 3:00 | 신뢰 상태와 확장 가능성을 설명한다. |

세부 연출과 장애 복구 경로는 [최종 발표 시연 기획](FINAL_DEMO.md)을 따른다.

## 실행

```bash
make setup
make dev
```

브라우저에서 http://localhost:5173을 연다.

## 데모 전 점검

- `make check`가 통과한다.
- 웹과 API 상태가 정상이다.
- 화면에 `합성 데모 데이터` 표시가 보인다.
- 네트워크가 끊겨도 fixture 데모가 동작한다.
- 원문 링크는 새 탭에서 열린다.
- 데모 입력과 예상 화면 전환을 미리 확인한다.
- 발표용 정책 원문과 추출 결과의 버전을 고정했다.
- PDF 또는 한글 파일 추출 실패에 대비한 텍스트 입력을 준비했다.
- 지도와 페르소나가 같은 시나리오 결과를 사용한다.
- 실제 투자 전망처럼 들리는 표현을 사용하지 않는다.
