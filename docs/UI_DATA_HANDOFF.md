# UI 및 실제 관측 자료 연결

## 이번 변경의 목적과 범위

정책입안자가 변경 내용, 지역 분포, 가구별 제약과 근거를 차례로 확인할 수 있도록 화면을 정리했습니다. `policymap-ui-design` 스킬의 정보 계층, 지도와 가구의 동시 표시, 출처의 단계적 공개 원칙을 적용했습니다.

구현 순서는 공개 자료 수집, 백엔드 계약 및 API 추가, 지도와 관측 자료 컴포넌트 구현, 화면 개편, 자동 테스트와 브라우저 검증입니다.

## 화면 구성

- `Workbench.tsx`: 정책 비교, 시점 선택, 가구 패널, 설명 경로와 연구 근거를 묶습니다.
- `ImpactMap.tsx`: 실제 행정경계를 SVG로 렌더링합니다. 타일 서버와 신규 지도 라이브러리에 의존하지 않습니다. 서울 확대, 키보드 지역 선택과 표 보기를 제공합니다.
- `ObservedPanel.tsx`: 선택 지역의 실제 신고 거래를 표시합니다. 면적 필터와 취소 포함 여부를 지원합니다. 단지와 조건이 다른 표본을 하나의 추세선으로 연결하지 않습니다.
- `public_data.py`: 공개 관측 자료의 모델과 로딩을 담당합니다. 합성 시뮬레이션과 분리되어 있습니다.

데이터 출처와 수집 한계는 `data/public/README.md`에 정리했습니다. API 필드와 프런트엔드 타입이 달라 예산이 비어 보이거나 행동 비중에 NaN이 나타나던 문제도 수정했습니다. KDI 연구의 잘못된 링크, 제목, 발간일을 원문 메타데이터에 맞췄습니다.

## 유지한 제한

현재 정책은 원문 대조 전의 합성 규칙입니다. 가격 범위는 검증된 예측이나 통계적 신뢰구간이 아닙니다. 가구 예산과 행동 비중은 고정된 데모 자료이므로 선택한 정책 조합에 따라 재계산되지 않습니다. 정책 완전성 백분율과 검증된 캐시처럼 보이던 배지는 화면에서 제거했습니다.

문서 입력은 TXT와 Markdown 읽기, 본문 붙여넣기와 임시 검토 메모를 지원합니다. PDF, HWP, HWPX의 자동 분석은 미연결로 표시합니다. 기존 API가 입력 내용과 무관하게 같은 스냅샷을 반환하므로 화면에서 이를 실제 추출 기능처럼 호출하지 않습니다. 원문 분석을 연결할 때 기존 `/api/v1/policies/extract`의 데모 동작을 먼저 대체해야 합니다.

교통 레이어는 아직 추가하지 않았습니다. GTX와 지하철은 정확한 좌표, 운행 상태와 기준일을 검증한 후 넣어야 하며, 노선 추가만으로 가격 상승효과를 부여하면 안 됩니다.

## 검증과 실행

```bash
make check
make dev
```

표준 포트는 웹 5173, API 8000입니다. 이 작업에서 확인한 기존 Antigravity 실행 인스턴스는 웹 5174와 API 8001입니다. 웹에서 `VITE_API_BASE_URL` 또는 `VITE_API_URL`로 다른 API 주소를 지정할 수 있습니다.

브라우저에서는 지역 선택, 시점 전환, 정책 체크박스, 가구 선택, 거래 면적 및 취소 필터, 상충 연구, 문서 입력, 오류 유지 동작과 390px 너비를 점검합니다. 실제 배포는 수행하지 않습니다.

## 검증 결과 (2026-10-16)

- `make check`에서 Python 린트, 백엔드 테스트 15개, 프런트엔드 테스트 9개, TypeScript 검사, Vite 빌드와 JSON 문서 33개 검증을 통과했습니다.
- 브라우저에서 지역 및 시점 전환, 지도와 표 전환, 전체 정책 펼치기, 상충 연구 표시를 확인했습니다.
- 강남구 표본은 취소 제외 시 6건, 포함 시 10건이며 80~90㎡ 필터에서는 취소되지 않은 2건이 표시됩니다. 미수집 지역은 빈 상태로 표시합니다.
- TXT 입력과 미지원 PDF 안내, Escape 닫기를 확인했습니다. API 오류를 주입하여 이전 시나리오 유지와 공공데이터 재시도를 점검했습니다.
- 390px 화면에서 가로 넘침과 NaN 표시가 없음을 확인했습니다. 브라우저 테스트 중 주입한 503 오류는 검증용이며 정상 서비스 오류가 아닙니다.
