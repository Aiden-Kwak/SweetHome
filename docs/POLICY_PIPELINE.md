# 새 정책 입력과 조건부 시뮬레이션

## 연결된 사용자 흐름

정책 문서 검토 화면에서 텍스트, PDF 또는 HWPX를 입력하고 자동 조문 추출을 실행한다. 변경 전후 수치가 명시된 규칙 후보 중 하나를 선택하고, 시행일, 지역, 가구 자격과 입력 금액을 검토한 뒤 새 정책 시뮬레이션을 실행한다. 결과 지도와 가구 패널은 같은 실험 결과를 사용한다. 기존 2025년 합성 시나리오를 새 정책의 결과로 대체하지 않는다.

입법예고 중이거나 시행일을 모르면 사용자가 시행을 가정하는 실험에 동의해야 한다. 실제 시행일을 입력하면 기준일이 시행일 이전인 경우 변경 전 조건을 유지한다.

## 자동 추출의 범위

- PDF는 pypdf로 실제 텍스트를 읽는다. 2MB, 60쪽 제한을 두며 암호화 문서와 텍스트가 없는 스캔 PDF는 거절한다. OCR은 연결하지 않았다.
- HWPX는 ZIP의 Contents/section XML에서 본문을 읽는다. 압축 해제 크기와 엔터티를 검사한다. 구형 HWP는 변환이 필요하다.
- Gemini 설정이 있으면 Google API로 본문을 전송해 규칙 후보를 추출한다. 모델 응답은 스키마, 원문 인용 위치, 변경 전후 수치의 존재 여부를 검사한다. 실패하면 오류를 표시하며 데모 결과로 대체하지 않는다.
- Gemini 설정이 없으면 자동 모드는 제한된 규칙 기반 추출임을 표시한다. 이 방식은 단위가 명시된 변경 전후 수치 쌍을 인식한다. 문장 구조가 복잡하거나 과거 값이 생략된 조문은 누락될 수 있다.
- 지원 항목은 주택담보대출 한도, 전세보증 한도, LTV, DSR, 연령, 세대수와 연면적 비율이다. 조세, 법적 예외, 경과규정과 복합 조건 전체를 추출한 것으로 간주하지 않는다.
- 후보는 실행 정책 원장에 승인된 PolicyRule이 아니다. 입력 URL의 공식성도 자동 검증하지 않는다.

## 계산 모형

시뮬레이션은 검토한 단일 규칙을 사용한다. 나머지 규제까지 결합한 실제 대출 승인액이 아니다.

| 규칙 | 계산 |
| --- | --- |
| 대출한도 | 규칙 한도와 가구 자금 수요 중 작은 값이다. |
| 보증한도 | 보증 범위와 자금 수요를 비교한다. 대출 승인액이나 매수 예산으로 해석하지 않는다. |
| LTV | 입력 주택가격에 비율을 곱한 단독 상한이며 자금 수요를 넘지 않는다. |
| DSR | 연소득에 비율을 곱한 값에서 기타 연간 상환액을 빼고, 입력 금리와 기간의 원리금균등 상환 현재가치로 환산한다. |
| 연령 | 적용 전후 연령 기준과 변화 폭을 표시한다. |
| 세대수, 연면적 비율 | 건축허가 경로 대상 여부를 비교하고, 지역별 공급 조건을 입력하면 공급 시점 변화와 가격 민감도를 계산한다. |

매매 금융 규칙에 사용자가 민감도 계수를 입력하면, 사례 가구의 예산 변화율 단순평균에 그 계수를 곱한다. 계수가 없으면 화면의 주요 지표를 구매 예산 변화로 전환한다. 전세보증은 보증 범위와 임차 예산으로 표시하며 매매가격과 혼동하지 않는다. 같은 조건의 지역에는 같은 값이 표시된다.

공급 정책에는 지역별 `supply_assumptions`를 입력한다. 기존 주택 수는 비교 기간 말의 기준 시나리오 주택 수이다. 사업 수, 사업당 세대수, 주거 연면적 비율, 부등호, 기간, 공급 전환 비율과 가격 반응 계수를 명시한다. 원문 요건 외의 사업 조건을 충족한다는 확인도 필요하다. 기준 완화가 주택 총량 증가를 자동으로 의미하지는 않는다.

공급 시점 변화는 `사업 수 × 사업당 세대수 × 전환 비율 × (변경 후 대상 여부 - 변경 전 대상 여부)`이다. 가격 민감도는 `-(공급 시점 변화 / 기준 주택 수 × 100) × 가격 반응 계수`이다. 전환 비율은 비교 기간 내 기준 시나리오보다 앞당겨지는 공급 비중이며, 신규 주택의 영구적 순증으로 해석하지 않는다. 단일 규칙 비교이며 나머지 요건은 충족한다는 입력 가정을 사용한다.

공급 입력에는 비교용 시작값을 자동으로 채우며 `input_basis=illustrative`로 저장한다. 직접 수정한 값은 지역을 추가해도 유지한다. 지역별 조건 편집은 접힌 영역에서 한 지역씩 선택하도록 구성했다. 시작값과 출처 구분은 [기본 입력값](INPUT_DEFAULTS.md)을 따른다. 출처 URL을 추가해도 실제 통계로 자동 인증하지 않는다. 모형 계수는 사용자 가정이며 추정 계수가 아니다.

결과에는 정책 유형에 맞는 지표, 지역별 계산 경로와 원문을 먼저 보여준다. 상세한 범위, 계산식과 재현 정보는 ‘계산 근거 및 적용 범위’에 모은다. 공급 결과에 무관한 가구 대출 카드나 ‘가격 미산출’ 문구를 반복하지 않는다.

가구 수치는 화면에서 수정할 수 있는 합성 사례이다. 적용 대상 체크는 기본 해제되어 있고 사용자가 확인한다. JEV 행동 확률, 수요 전이, 거래량 예측과 지역별 추정 계수는 이번 계산에 포함하지 않는다.

## API와 재현성

- `POST /api/v1/policies/analyze`: 텍스트 또는 Base64 파일 중 하나를 받는다. 파일 해시, 텍스트 해시, 처리 시각, 처리 방식, 정확한 인용문과 문자 위치를 반환한다.
- `POST /api/v1/scenarios/policy`: 원문, 선택 후보, 검토 확인, 지역, 가구 입력, 시행일, 기준일과 선택적 민감도 계수를 받는다. 원문 근거를 다시 검증하고 결정식으로 계산한다.
- 기존 `/api/v1/policies/extract`는 명시적인 sample 요청만 허용한다. 실제 입력을 합성 정책으로 대체하던 경로는 HTTP 410으로 차단했다.
- API는 `data_status=INCOMPLETE`, `model_status=EXPERIMENTAL`, `model_version=policy-constraints-v2`를 반환한다. UI는 ‘입력 가정 기반 시나리오’로 풀어 표시하며, 실제 가격 전망과 구분한다.
- 실험 ID는 모형 버전과 정렬된 요청 JSON의 SHA-256으로 생성한다. 같은 입력과 모형 버전에서 같은 결과를 만든다. 원문과 모든 계산 조건은 JSON으로 내보낼 수 있다.
- 서버 원장 저장이나 지식그래프 자동 갱신은 하지 않는다. 결과 창을 닫아도 현재 탭에서 입력과 결과를 유지하며 첫 화면에서 다시 열 수 있다. 새로고침하거나 새 문서로 시작하기 전에 결과 JSON을 저장한다.
- 행정경계는 기존 2018년 자료를 사용한다. 통계청 코드에는 `kostat:` 접두사를 붙여 국가 행정구역 코드와 충돌하지 않게 한다. 최신 법적 구역 확인은 별도로 필요하다.

## Gemini 설정

API 프로세스에 `GEMINI_API_KEY`와 실제 사용 권한이 있는 `GEMINI_MODEL`을 설정한다. 모델 이름을 임의로 기본 지정하지 않는다. 로컬에서 비밀값을 .env.local에 저장한 경우 다음과 같이 읽게 할 수 있다.

```bash
uv run --project services/api uvicorn policymap_api.main:app --env-file .env.local --host 0.0.0.0 --port 8001
```

이미 8001 포트의 API가 실행 중이면 설정을 반영하여 재시작해야 한다. Cloud Run에서는 서버 환경 변수와 Secret Manager를 사용한다. 브라우저 환경 변수에 API 키를 넣지 않는다.

Gemini 어댑터의 오류 처리는 모의 응답으로 테스트했다. 2026년 10월 16일에는 행사 계정의 `gemini-4-argon`을 실제 호출하고, Cloud Run API에서도 두 공식 검토 요약의 추출과 조건부 계산을 확인했다. 전세보증 한도 2억 원에서 3억 원, 세대수 300에서 500과 연면적 비율 90%에서 100%의 변경을 추출했고 원문 인용 검사를 통과했다. 이 확인은 해당 예시의 동작 점검이며 전체 법령 추출 품질 평가를 의미하지 않는다. 배포 절차는 [Cloud Run 안내](../infra/cloudrun/README.md)에 있다.
